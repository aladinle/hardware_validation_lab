# M2B.3 - bounded standalone local runner

Implemented locally for review on branch `codex/m2b.3-bounded-local-runner`. **Do not merge into main without the user's explicit approval.** No commit/push/merge is implied by this checkpoint. This task supervises local synthetic plugin processes, not queued jobs, backend Attempts, hardware leases, persistent restart reconciliation or physical devices. M2B.4 remains a separate continuation. Actual results and limitations are in [STATUS.md](STATUS.md).

## What changed

The fixed worker performs prepare/execute/collect/cleanup: validate the manifest and installed artifact, copy bounded explicit expected/actual inputs and wheel into a new private work directory, run the installed CAN comparator in a separate child, validate/retain its versioned report and clean only acquired files with unchanged identities. No shell, executable path, import path or remote-supplied host path is accepted by the worker. Operator-selected local file paths exist only at this standalone CLI boundary. The agent's network heartbeat remains idle; no backend endpoint dispatches this runner.

On Windows, create the child suspended, attach it to a Job Object, resume it, and send a launch gate before loading the plugin. Job Objects apply committed-memory, aggregate user-CPU-time, active-process and CPU-rate hard limits plus kill-on-close. Root exit alone does not establish stopped descendants: query job accounting until active process count is zero. Cancellation first sends a cooperative pipe message, waits a bounded grace period, then terminates the job tree if required. The parent strips environment secrets; only OS system/temp variables are inherited. Host antivirus behavior/trust settings are preserved.

On Linux, start a new process session/group and hold the same plugin launch gate. The worker applies RLIMIT_AS (per-process address space), RLIMIT_CPU (per-process, rounded up to whole seconds), and RLIMIT_FSIZE (per-file). Parent monitors working-directory total size and group process count, then escalates with SIGKILL to the group. /proc observations confirm group members are no longer executing (zombies are stopped, not running work). Linux requires --cpu-percent 100: no CPU-rate throttle is implemented. Process count is monitored, not a kernel cgroup limit; CPU/memory limits are per process, not aggregate job limits. No cgroup/host configuration is installed or changed. These controls support trusted installed plugins and fixed probes, not hostile code that deliberately escapes sessions or changes OS identity. WSL testing is not Linux service or physical-hardware proof.

## Limits and result meaning

Defaults: 10-second execution wall deadline, 0.5-second stop grace, five user CPU seconds, 256 MiB memory, 8 MiB retained stdout, 64 KiB stderr, 40 MiB working-directory budget and at most four processes. Windows CPU rate defaults to 50%; Linux CLI defaults to 100% with no throttle. Bounds are validated; NaN, booleans, invalid ranges and unknown commands are rejected. Input staging remains at most 1 MiB per role and 20 MiB per wheel. Parent-controlled staging is admitted against the disk budget; the work directory is monitored during execution. Monitoring is a soft aggregate budget with possible polling overshoot, not an OS-wide disk quota. Linux additionally enforces a hard per-file limit. Fixed production CAN code performs pure file analysis; OS temp/cache/monitoring activity is outside that work-directory budget. No new OS sandbox claim is made.

stdout/stderr are drained concurrently and retained only up to their caps; overflow stops execution rather than growing buffers indefinitely. No pipe buffer lock is held across blocking reads. Worker output is checked for duplicate keys/nonfinite values, supported schema/source/outcome, matching raw/normalized evidence and package identity, approved parameters, counters and bounded details. Malformed output is infrastructure ERROR. Local run.json includes limits, platform/version, reason, exit code, accounting, forced termination, cleanup, evidence and uncertainty status. Comparison reports remain deterministic; timing/process metadata belongs separately to run.json.

| Condition | Primary outcome | CLI exit |
| --- | --- | --- |
| Matching payloads | PASS / EVALUATED | 0 if cleanup/evidence/termination complete |
| Product byte mismatch | FAIL / EVALUATED | 1 if otherwise complete |
| Invalid data, setup, crash, malformed output, overflow, disk/process limit | ERROR / NOT_EVALUATED | 2 |
| Execution wall deadline | TIMEOUT / NOT_EVALUATED | 2 |
| Cooperative or escalated cancellation | CANCELLED / NOT_EVALUATED | 2 |
| PASS with cleanup failure or incomplete evidence | Preserve PASS; separate failure status | 2 |
| Cannot confirm stopped processes | Preserve original outcome, defer cleanup, quarantine_required=true | 2 |

A CPU/memory OS-limit exit is reported as infrastructure ERROR/CHILD_EXIT, not guessed to be a product FAIL or a specific hardware failure. Raw stdout/stderr remain available within bounds. Timeout remains TIMEOUT even if the cooperative worker acknowledges cancellation. Cancellation before launch creates no worker. A second interrupt/evidence-write problem cannot be counted as a clean result.

Only exact registered regular files whose identities match are removed; unknown files, symlinks/reparse changes and failed deletions remain as evidence. There is no recursive cleanup of arbitrary paths. If termination is uncertain, cleanup is deferred. `quarantine_required` is a local handoff flag, not an implemented SQL quarantine allocator. It prevents a successful CLI exit and requires reconciliation before any future resource reuse. Even confirmed zero processes does not establish physical device readiness: hardware_readiness always remains NOT_EVALUATED.

```powershell
.\.venv\Scripts\python.exe -m build --no-isolation --sdist-extract-dir .local/build-b3-review --outdir .local/dist-b3-review
.\.venv\Scripts\python.exe -m venv .local/b3-runner-venv

```

Do not recreate a pre-existing environment blindly. The installed package is Django-free and adds hvl-runner. It includes the unchanged CAN algorithm version 0.3.0 in distribution 0.4.0; its new wheel digest must match the supplied manifest. Historical 0.3.0 environments/manifests stay separate; do not reuse an old digest with this new runner package. No webserver/database/agent credential is required for this local demo.

## Five-minute demo and manual test steps

Use a second PowerShell window from the project root. All output names below must be new; choose a suffix if they already exist. Leave main unchanged while reviewing this feature branch.

1. Minute 0-1: create a candidate local manifest. This does not grant SQL approval or dispatch authority.

```powershell
.\.local\b3-runner-venv\Scripts\hvl-compare.exe manifest --wheel .local/dist-b3-review/hardware_validation_lab_contracts-0.4.0-py3-none-any.whl --header-bytes 2 --output .local/b3-demo-manifest.json
```

2. Minute 1-2: run PASS through the supervised child, then inspect its lifecycle record.

```powershell
.\.local\b3-runner-venv\Scripts\hvl-runner.exe run --manifest .local/b3-demo-manifest.json --wheel .local/dist-b3-review/hardware_validation_lab_contracts-0.4.0-py3-none-any.whl --expected examples/can/expected-header.hex --actual examples/can/actual-pass.hex --header-bytes 2 --output-dir .local/b3-demo-pass
$LASTEXITCODE
Get-Content .local/b3-demo-pass/run.json
Get-Content .local/b3-demo-pass/report.txt
```

Expect PASS, exit 0, termination_confirmed=true, cleanup_status=COMPLETE, quarantine_required=false and hardware_readiness=NOT_EVALUATED. Repeat with actual-mismatch.hex and a new output directory: expect FAIL/exit 1 with payload offset 2, AA versus AB. actual-invalid.hex gives ERROR/exit 2; no evaluated product assertion.

3. Minute 2-3: use a fixed synthetic uncooperative-worker probe to test deadline and forced termination.

```powershell
.\.local\b3-runner-venv\Scripts\hvl-runner.exe probe --scenario ignore_cancel --timeout 1 --grace 0.3 --output-dir .local/b3-demo-timeout
$LASTEXITCODE
```

Expect TIMEOUT/WALL_TIMEOUT, exit 2, forced_termination=true and confirmed stopped tree. Try --scenario descendant with a fresh directory to verify multiple counted processes are stopped together.

4. Minute 3-4: demonstrate cancellation. Run this command, wait about one second, then press Ctrl+C once in its PowerShell window.

```powershell
.\.local\b3-runner-venv\Scripts\hvl-runner.exe probe --scenario cooperative --timeout 30 --output-dir .local/b3-demo-cancel
$LASTEXITCODE
```

Expect CANCELLED/CANCEL_REQUESTED, exit 2 and normally forced_termination=false. Check run.json. Using ignore_cancel instead should require escalation after the grace period. Final process-stop confirmation is separate from the cancellation request.

5. Minute 4-5: demonstrate malformed output and independent cleanup status using fresh directories.

```powershell
.\.local\b3-runner-venv\Scripts\hvl-runner.exe probe --scenario malformed --output-dir .local/b3-demo-malformed
$LASTEXITCODE
.\.local\b3-runner-venv\Scripts\hvl-runner.exe probe --scenario cleanup_error --output-dir .local/b3-demo-cleanup
$LASTEXITCODE
```

Malformed -> ERROR/MALFORMED_OUTPUT/exit 2. On Windows the cleanup probe creates one owned read-only fixture file: its evaluated PASS/report are preserved, cleanup_status=ERROR and exit 2. The retained work/fixture.tmp is intentional review evidence; no live process is kept running. POSIX deletion rules differ, so this is a Windows-specific cleanup-failure demonstration.

Additional fixed probes:

| Scenario | Expected result |
| --- | --- |
| pass | Synthetic probe PASS, complete cleanup, exit 0 |
| crash | ERROR/CHILD_EXIT, exit 2 |
| overflow / stderr_overflow | ERROR/OUTPUT_LIMIT, capped binary evidence, exit 2 |
| prepare_error | ERROR/SETUP_ERROR, no worker PID, only acquired files cleaned |
| memory, with --memory-mb 64 --timeout 5 | OS allocation failure -> ERROR/CHILD_EXIT |
| cpu, with --cpu-seconds 1 --timeout 5 | OS CPU-time limit -> ERROR/CHILD_EXIT |
| disk | Reaches working disk budget or wall deadline first; reason identifies which. Native tests use smaller budgets to prove DISK_LIMIT; Linux may hit hard per-file limit first |

A probe is labeled source=runner_probe and is not a physical device result. Attempts to supply --command/unknown scenarios, change the declared header or reuse an output directory fail safely. Do not paste credential JSON into runner reports or command arguments.
