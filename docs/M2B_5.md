# M2B.5 - PostgreSQL assignment and native polling

Implemented locally for review on `codex/m2b.5-postgres-assignment-polling`. M2B.4 was approved, merged and pushed; M2B.5 is uncommitted and unmerged. Stop before M2B.6. Actual commands/results are in [STATUS.md](STATUS.md).

## What changed

An opt-in foreground scheduler commits one immutable Attempt and exclusive PostgreSQL leases before an authenticated native agent can receive it. The Attempt ID is the execution ID. Current requester/account/session epoch, membership, explicit version/device grants, approval, original service-token identity/scope, immutable inputs, simulated inventory binding, capabilities and package digest are checked again at allocation and claim/input/receipt time. Logout alone does not invalidate a submitted job; security epoch changes do. Old snapshots without the new authority fields must be resubmitted, never rewritten.

The allocator locks a global single-worker resource, then requester/project/agent and ordered resource rows. Unique unreleased leases protect the global worker, agent, device and explicitly configured shared station. Two concurrent PostgreSQL allocators were tested. This gate intentionally permits one assignment per agent/job and holds the global slot after completion. It is not M3's parallel scheduler/recovery proof.

Only enabled `source=simulated` inventory with an administrator-configured approved version and actual matching wheel is eligible. Ordinary M2A metadata-only jobs remain queued and cannot execute. The separate poller obtains role-scoped bounded input bytes, verifies their hashes, rechecks its claim, and invokes the existing journal/contained runner. Duplicate polling uses the same execution ID/epoch and does not launch again. It pins its journal to the authenticated backend origin and rejects reuse of a local-demo journal. Package self-reporting is not remote attestation of a hostile machine.

The backend accepts only a completion digest/control receipt: `awaiting_evidence`. The report and PASS/FAIL/ERROR remain local. `evidence_acknowledged=false`, `leases_released=false`, `hardware_ready=false`. Server assignments cannot use the fake local-demo ACK. M2B.6 must implement authorized result/evidence ingestion and acknowledgement; no SQL PASS result, automatic lease release or new result browser is claimed here.

## Once-only preparation

Use a separate synthetic review scope. Keep existing results/journals; do not erase a held allocation to repeat the demo. This gate has no release/reconciliation command. A finished demo deliberately holds the global slot.

1. Stop the old web process before changing its source/schema. New additive migrations are 0005/0006. The user's existing `hardware_lab_m2a` was **not** upgraded during this review. The test runner creates/destroys its own test database. `scripts/postgres-local.ps1` selects `hardware_lab_m2a`; use explicit environment settings and manage.py for another database.
2. Set `$env:LAB_SIMULATOR_DISPATCH='1'` in the web and scheduler shells. Default is 0. Restart web with the same PostgreSQL and secret settings: `.\.venv\Scripts\python.exe web/manage.py runserver 127.0.0.1:8765 --noreload`. Never enable this flag to make physical inventory runnable.
3. Build the actual package: `.\.venv\Scripts\python.exe -m build --no-isolation --outdir .local/dist-b5`. Create a clean native environment with `python -m venv .local/b5-agent-venv`, then install the wheel using its Python and `-m pip install --no-index --no-deps PATH_TO_WHEEL`. Use the same immutable wheel for backend publication/configuration and agent polling. Review release is 0.6.0; CAN algorithm remains 0.3.0.
4. Follow [M2B_1.md](M2B_1.md) to enroll an agent bound only to your synthetic device. Substitute paths; these uppercase labels are placeholders. Enrollment files expire and are single-use. Never paste tokens into arguments/logs/Git. Do not promote a historical metadata version/job.
6. Configure the exact binding in the trusted backend shell:

```powershell

  --project PROJECT_UUID --agent AGENT_UUID --device DEVICE_UUID `
```

Use IDs from your scope and the administrator's actual email. This audits configuration, not assignment. A new journal root must belong to this one agent/runtime/backend; never clone it or initialize a replacement to bypass dedup.

## Five-minute demo

Use the native environment's `python.exe` as `NATIVE_PYTHON` below. Set private state and wheel paths from preparation; commands contain file paths, not tokens. Keep both backend shells configured against the same PostgreSQL database. The single allocation lease is fixed at 90 seconds; perform steps 2-3 immediately.

1. Minute 0-1: `NATIVE_PYTHON -m agent.poller --state-file STATE_PATH --journal-root NEW_JOURNAL_PATH --wheel WHEEL_PATH --init-journal`. Expected: `assignment_received=false`, `hardware_ready=false`, exit 0. This authenticated execution poll supplies 30 seconds of freshness for allocation. An ordinary heartbeat alone does not supply that freshness. Later commands omit `--init-journal`.
2. Minute 1-2, separate backend shell: `.\.venv\Scripts\python.exe web/manage.py scheduler --confirm-simulated --iterations 1`. Expect one execution ID. PostgreSQL now contains one immutable Attempt and four unreleased leases. The scheduler is a separate process; HTTP never runs the plugin. A missing policy/flag, stale poll or revoked permission prevents allocation. A policy-matched rejected job can become `blocked`; resubmit after fixing authority, preserving the old request.
3. Immediately: `NATIVE_PYTHON -m agent.poller --state-file STATE_PATH --journal-root JOURNAL_PATH --wheel WHEEL_PATH --count 2 --interval 1`. Expect the same execution ID/epoch twice: first `newly_accepted=true`, then false; `journal_state=COMPLETE`, `local_outcome=PASS`, `receipt_recorded=true`. Both say evidence acknowledgement/release/readiness are false. There is one observed persisted spawn. The local spool retains the JSON/human report and checksummed completion seal. This is synthetic file comparison, not CAN hardware capture.
4. Minute 2-3: inspect your journal's retained report and use trusted read-only Django ORM inspection of Attempt/Lease. Expect `awaiting_evidence`, a receipt digest, four unreleased leases, no backend test outcome. Repeated polls within the deadline do not rerun. Do not use the local-demo ACK on this server execution; it must reject it.
5. Minute 3-5: revoke the requester's explicit device grant in the portal, then repeat polling. Expected: sanitized rejection and `$LASTEXITCODE` equal to 2, with evidence/ownership retained. Machine heartbeat can still succeed if the agent's own credential/scope remains valid: requester authority and machine identity are separate. Alternatively, let the 90-second lease expire, run one scheduler cycle, and verify quarantine with the four leases still held. Expiry does not prove that a process/hardware stopped. Do not clear quarantine, delete the journal or manually release SQL leases to restart the demo.

Linux live HTTP polling, macOS, OS power loss, hardware, phone browser flows, hosted CI and M3 parallel recovery remain unverified. Actual desktop review covered a labeled inactive-form snapshot of the real agent template and no horizontal overflow, not browser authentication. Docker Compose configuration parsed, but the Docker engine was unavailable, so container integration was not run.

One early console enrollment attempt consumed its ticket without persisting local state; the precise cause is unproven. Explicit administrator reissue revoked the lost key; a fresh module-entry enrollment succeeded. No security monitoring, TLS verification or browser security was disabled.

Claims bind execution/agent/epoch via server HMAC, with only their digest stored in SQL; changing the server secret requires reconciliation of outstanding allocations. Claims and runtime tokens travel in authenticated POST traffic, never URLs. Bearer agent routes have no session/CI fallback; browser mutations retain CSRF checks. There is no broker boundary yet and no outbox required at this gate. Result upload/ACK, cancellation and portal execution integration remain .6/.7/.8.
